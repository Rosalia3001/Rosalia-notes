## 1. 什么是 GitHub

- **Git**：2005 年 Linus 为管理 Linux 内核开发的分布式版本控制工具，跑在自己电脑上，记录「谁在什么时候改了什么」
- **GitHub**：2008 年上线的代码托管平台，给 Git 仓库提供一个云端的家，外加协作功能（2018 年被微软收购）
- 关系：**没有 GitHub，Git 照样能用；没有 Git，GitHub 无从谈起**
- 能放的东西不只有代码：文档、笔记、配置、图片，甚至整站（GitHub Pages）

## 2. 找资源的 4 个方法

视频讲了哪 4 种我无法确认，下面是我自己在用的四种，作用互补：

| 方法 | 入口 | 适合 |
| --- | --- | --- |
| 搜索语法 | 顶部搜索框 | 精确找：`topic:llm stars:>1000 language:python` |
| Trending | `github.com/trending` | 看最近什么在涨，可按语言 / 日周月筛 |
| Topics | `github.com/topics` | 按领域逛，比关键词搜索更宽 |
| awesome 清单 | 搜 `awesome 关键词` | 找「别人已经整理好的清单」，最省时间 |

补充两招：**Follow 靠谱的人和组织**，他们的 star 列表就是现成的推荐；遇到好项目先 **Star** 存档，别指望记住。

## 3. 界面与基本概念

| 概念 | 含义 | 容易混淆的点 |
| --- | --- | --- |
| Repository | 仓库，一个项目 | 一个仓库 ≠ 一个文件夹，它带完整历史 |
| Star | 收藏 + 点赞 | 只是标记，**不会**复制代码到你账号 |
| Fork | 把别人的仓库复制一份到你账号下 | 复制品，可以随便改，改动不会自动回到原仓库 |
| Watch | 订阅通知 | 分「全部 / 只关注 Issue / 忽略」多档 |
| Issue | 问题与讨论 | 不只是报 bug，也用来提需求、讨论方案 |
| Pull Request | 合并请求 | 把自己的改动「申请」合并进目标仓库 |
| Release | 发布版本 | 挂版本号 + 安装包 + 更新说明 |
| Actions | 自动化流水线 | 提交后自动测试 / 构建 / 部署 |

仓库页顶部几个标签页：`Code`（文件与 README）、`Issues`、`Pull requests`、`Actions`、`Projects`、`Wiki`、`Insights`。看一个陌生项目，**先读 README，再看 Releases 和 Issues 的活跃度**。

## 4. GitHub 的工作原理

Git 的四个区域，改动沿着箭头走：

```
工作区(你改的文件) → 暂存区(git add) → 本地仓库(git commit) → 远程仓库(git push)
```

- `git clone` / `git pull`：把远程拉到本地
- `git add`：挑选这次要提交哪些改动（暂存区就是「待提交清单」）
- `git commit`：把暂存区打成一个快照，附一句说明
- `git push`：快照推到远程

协作流程（开源项目标准姿势）：

```
Fork → clone 到本地 → 建分支 → 改 → commit → push 到自己仓库 → 提 PR → 作者 review → merge
```

**分布式**的含义：每个人本地都有一份完整历史，断网也能 commit，恢复力强。

## 5. 七种常见开源许可证

| 许可证 | 类型 | 衍生作品必须开源？ | 要点 |
| --- | --- | --- | --- |
| MIT | 宽松 | 否 | 最短最常用，保留版权声明即可 |
| Apache-2.0 | 宽松 | 否 | 额外含**专利授权**，企业友好 |
| BSD-2 / 3-Clause | 宽松 | 否 | 3-Clause 多一条「不得用作者名义背书」 |
| MPL-2.0 | 弱传染 | 改动的**文件**要开源 | 文件级传染，可与其他许可共存 |
| LGPL | 弱传染 | 动态链接可闭源 | 常用于库 |
| GPL-2.0 / 3.0 | 强传染 | 是 | 衍生作品必须同样 GPL 开源 |
| Unlicense / CC0 | 公共领域 | 否 | 放弃一切权利，最自由 |

怎么选：**个人小项目直接 MIT**；想让别人放心用、涉及专利就 Apache-2.0；想让改进必须回流社区就 GPL。反过来，**用别人的 GPL 代码要小心**，自己的项目可能被迫开源。

## 6. 四种下载使用方式

| 方式 | 操作 | 适用 | 代价 |
| --- | --- | --- | --- |
| Download ZIP | Code 按钮 → Download ZIP | 只想看一眼源码 | 没有历史，不能 `pull` 更新 |
| `git clone` | 命令行 | 开发、需要跟进更新 | 要装 Git |
| Release 产物 | Releases 页下载 | 普通用户装软件 | 只有作者打包的版本 |
| 图形客户端 | GitHub Desktop / 网页上传 | 不想碰命令行 | 功能受限 |

判断标准很简单：**你要不要跟着项目更新？** 要就用 clone，不要就用 ZIP。

## 7. 创建并开源第一个项目

网页端点 `New repository`，四个选项别乱选：

- **仓库名**：小写英文 + 连字符
- **Public / Private**：公开才能被别人看到；私有只有自己和协作者
- **Add a README**：勾上，否则仓库是空的
- **.gitignore / License**：模板直接选，省事

本地已有项目推上去：

```bash
git init
git add .
git commit -m "feat: 初始提交"
git branch -M main
git remote add origin https://github.com/<用户名>/<仓库名>.git
git push -u origin main
```

**开源三件套**：README（这是什么、怎么用）、LICENSE（授权）、.gitignore（别把垃圾和密钥传上去）。

## 术语速查

- **commit**：一次快照，附说明
- **branch**：平行分支，互不干扰
- **merge**：把分支合回来
- **conflict**：两人改了同一处，需手工决定留谁
- **origin / upstream**：默认远程 / 上游原仓库
- **HEAD**：当前所在位置
- **tag**：给某个 commit 起名，通常标版本号

## 和我的笔记仓库对照

这个仓库本身就可以当练手样本：

- `README.md` 对应「这是什么、怎么用」
- `notes/` 下的 md 文件就是被版本控制的普通文件
- 每次写完 commit 一次，历史里能翻到任何一天的版本
- 文件名带日期前缀，文件夹排序天然就是时间线
- 仓库是 **private**，只有自己可见，练手不怕丢人
