# 学习资料

个人学习笔记仓库。不预设学科目录，靠**日期 + 标签**组织，写完全部自动汇总成索引。

## 怎么用

```bash
# 1. 复制模板，按规范命名
cp templates/note.md notes/2026/10/2026-10-20-某个主题.md

# 2. 写内容（填好开头的 front matter）

# 3. 重新生成索引
python scripts/build_index.py
```

三步之后，根目录的 [`INDEX.md`](INDEX.md) 会自动更新，按时间和标签两个维度列出所有笔记。

## 目录结构

```text
.
├── README.md            # 本文件：约定与用法
├── INDEX.md             # 自动生成的笔记索引，勿手改
├── notes/               # 所有笔记，按 年/月 存放
│   └── 2026/10/2026-10-20-hello-notes.md
├── templates/           # 模板，写之前复制一份
│   ├── note.md          # 学习笔记
│   ├── reading.md       # 读书 / 文章笔记
│   └── weekly.md        # 周复盘
├── scripts/
│   └── build_index.py   # 扫描 front matter 生成 INDEX.md（零依赖）
└── assets/              # 图片等附件
```

## 命名规范

```
notes/YYYY/MM/YYYY-MM-DD-简短英文slug.md
```

例：`notes/2026/10/2026-10-20-prompt-caching.md`

- 文件名以小写英文和连字符为主，避免中文文件名（跨平台和链接更稳）
- 日期前缀保证按时间自然排序，也是脚本识别笔记的依据

## 每篇笔记的头部

用 YAML front matter，字段固定为这五个：

```yaml
---
title: 标题
date: 2026-10-20
tags: [llm, prompt]
status: draft
source: https://example.com
---
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 索引里显示的标题 |
| `date` | 是 | `YYYY-MM-DD`，用来排序 |
| `tags` | 否 | 数组，可以多个：`[llm, prompt]` |
| `status` | 否 | `draft` 草稿 / `done` 完成 / `wip` 进行中 |
| `source` | 否 | 原始出处链接，读书笔记用得上 |

字段缺失或文件名不合规时，脚本会打印提醒，但仍然照常生成索引。

## 写作约定

这几条是为了让半年后的自己还看得懂，不是形式要求：

1. **开头先写一句话结论**——这篇笔记到底解决了什么问题
2. **区分「事实」和「我的判断」**——前者可查证，后者会过时，标清楚
3. **卡住的地方直接写「我还没搞懂」**——别装作懂了，悬念就是下次的入口
4. **贴代码必须带语言标记**，方便高亮和日后复制
5. **草稿直接提交**，`status: draft` 就是给不完整的内容留的位置，不必等写完再保存

## 索引说明

`INDEX.md` 由 `scripts/build_index.py` 生成，包含：

- **按时间**：日期、标题、标签、状态四列表格
- **按标签**：按标签分组，条目多的标签排在前面

脚本零依赖（只用 Python 标准库），任何机器上 `python scripts/build_index.py` 都能跑。所有 Markdown 链接都是相对路径，在 GitHub 和本地编辑器中都能直接跳转。

## 关于内容边界

这是私有仓库，但仍建议遵守：

- 公司内部文档、账号口令、真实业务数据不往上贴；需要记录时写**结论和方法**，不搬**原文和数据**
- 引用他人文章时保留出处链接，大段引用请注明
- 图片放 `assets/`，大文件尽量压缩后再提交
